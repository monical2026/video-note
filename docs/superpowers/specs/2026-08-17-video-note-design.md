# Video Note 浏览器插件 · 设计文档

- 日期：2026-08-17
- 状态：已与用户逐节确认
- 目标平台：Chrome / Edge（Manifest V3）

## 1. 背景与目标

**痛点**：看网页视频教程时，遇到有价值/有疑惑的内容想做笔记，必须切换到其他页面或 app，流程繁琐。

**目标**：一个浏览器侧边栏插件，看视频时不出页面即可：

1. 获取带时间戳的逐字稿，支持中英对照 / 纯中文 / 纯英文切换
2. 对任意片段做笔记（时间戳 + 原文摘录 + 批注 + 类型标记）
3. AI 能力：疑惑解释、视频摘要、知识点提炼
4. 导出一份融合好的完整学习笔记（Obsidian 友善），单条笔记可复制

**硬性原则**：分版本迭代，第一版聚焦核心，不一次全塞。

## 2. 版本划分

| 版本 | 内容 |
|------|------|
| **V1（本设计实施范围）** | YouTube 逐字稿双通道获取、三档显示切换（免费翻译默认 + LLM key 升级 + LLM 纠错润色开关）、两种方式记笔记、AI 解释疑惑、AI 摘要/知识点、按视频归档本地存储、单条复制、融合导出 Markdown |
| **V2** | 飞书一键导入、跨视频主题分类（手动归类 + AI 建议，锚点=知识点清单）、逐字稿跨视频搜索 |
| **V3+** | 其他站点适配（B站/Coursera 等，逐站新增 adapter） |

注：原 V3 规划的「自建音频识别」已砍掉——Supadata 兜底通道已覆盖无字幕场景，不重复建设。

## 3. 产品形态

### 3.1 侧边栏布局（Side Panel，视频旁常驻）

```
┌─────────────────────────────┐
│ 视频标题              ⚙️设置 │
│ [逐字稿] [笔记] [AI 摘要]     │ ← Tab 切换
├─────────────────────────────┤
│ 显示模式: 中英对照|仅中文|仅英文 │
│                             │
│ 03:12 We can use closures…  │ ← 当前播放句高亮
│      我们可以利用闭包…        │    自动滚动跟随
│ 03:18 to capture state...   │
│      来捕获状态…             │
│      （选中字幕 → 浮出✏️记笔记）│
├─────────────────────────────┤
│ 💡 类型: ⭐有价值 / ❓有疑惑    │
│ ✍️ 批注输入…                  │
└─────────────────────────────┘
```

### 3.2 逐字稿 Tab

- 三档显示切换：中英对照 / 仅中文 / 仅英文
- 当前播放句高亮 + 自动滚动跟随
- 点击任意时间戳 → 视频跳转到对应位置
- 长逐字稿虚拟滚动渲染

### 3.3 笔记 Tab

- 本视频笔记列表：时间戳 + 原文摘录 + 批注 + 类型标签（⭐有价值 / ❓有疑惑）
- 「有疑惑」笔记带「AI 解释」按钮：LLM 结合上下文解释 → 可编辑 → 随笔记保存
- 每条笔记带两个操作按钮：
  - **复制**：复制该条完整格式（时间戳 + 类型 + 批注 + 摘录 + AI 解释，与融合导出格式一致）
  - **跳转**：跳回该笔记对应的视频时间点。当前视频内直接 seek；从历史笔记库进入时，打开对应视频并经 URL 时间参数（`&t=xxs`，YouTube 原生支持）精准定位
- 底部「导出 Markdown」

### 3.3a 历史笔记库（视频库）

侧边栏顶部「📚」图标按钮 → 视频库列表：

```
┌─────────────────────────────┐
│ ← 返回        历史笔记        │
├─────────────────────────────┤
│ 🔍 搜索视频标题…              │
│                             │
│ ▸ 闭包详解 ｜ 笔记 5 条 ｜ 8/15│
│ ▸ React 入门 ｜ 笔记 12 条 ｜ 8/14│
│ ▸ CSS Grid ｜ 笔记 2 条 ｜ 8/10│
└─────────────────────────────┘
```

- 每项：视频标题、笔记条数、最近记录时间，按时间倒序
- 点进任意历史视频：与当前视频笔记 Tab 相同的视图（复制、跳转、导出可用；跳转按钮会打开该视频并定位时间点）
- 存储依据：每条笔记带 `videoId` 存本地 IndexedDB，永久保存，切视频/关浏览器不丢，仅手动删除才删
- V2 的「主题分类」在此列表之上再加分组维度

### 3.4 AI 摘要 Tab

- 手动点「生成摘要」触发（不自动，token 花费用户可控）
- 输出结构（展示与存储同一份结构化数据）：
  1. 一句话总结
  2. 内容摘要：分要点，每条带时间戳（可点击跳回视频）
  3. 知识点清单：概念 + 简要说明（V2 主题分类的锚点，数据结构 V1 埋好）
  4. 前置知识 / 延伸
- 超长视频分块摘要再汇总（map-reduce，防超上下文窗口）
- 生成后缓存，可「重新生成」
- 依赖：需配置 LLM key（免费翻译通道无此能力，未配置时禁用并提示）

### 3.5 记笔记的两种触发方式（V1 都要）

1. **选中记笔记**：在逐字稿上选中一段 → 浮出「记笔记」→ 选类型 → 写批注 → 保存
2. **快捷键截取**：快捷键（`chrome.commands`，默认 Ctrl+Shift+N）→ 自动抓当前播放时间点 ± 上下文字幕 → 笔记编辑
   - 快捷键自定义入口：浏览器统一管理页 `chrome://extensions/shortcuts`（Edge: `edge://extensions/shortcuts`），插件无权代改（浏览器安全机制）；插件设置页提供「修改快捷键」按钮直接跳转

### 3.6 融合导出（默认导出形态）

以时间轴为骨架，程序化融合（不经过 LLM 重写，批注原样保留、零成本）：

```markdown
---
title: 视频标题
source: https://youtube.com/watch?v=xxx
channel: xxx
date: 2026-08-17
---

# 视频标题

> 📌 一句话总结：……

## 03:12 闭包的定义与直觉          ← AI 摘要分节（可跳回视频）
摘要内容……

> ⭐ **我的笔记** · 03:15
> 闭包 = 函数记住它出生时的环境
> 「We can use closures to capture state…」

## 08:45 三个经典使用场景
摘要内容……

> ❓ **我的疑惑** · 09:02
> 这里和作用域链是什么关系？
> 🤖 **AI 解释**：……

## 📚 知识点清单
- 闭包 (closure)：……
```

规则：

- 文中所有时间戳均输出为 YouTube 跳转链接（`链接地址&t=秒数`），Obsidian 中可点击直达
- 笔记按时间戳嵌入所属摘要小节
- 未生成摘要 / 笔记落在小节之间 → 退化为纯笔记时间线（同样融合为单文档）
- 导出选项：完整融合笔记（默认）/ 仅我的笔记 / 是否附加完整逐字稿附录
- 单条复制格式与此一致

## 4. 技术架构

技术栈：**WXT 框架 + TypeScript + Preact**（基于 Vite，MV3 一等支持，热更新）。

### 4.1 模块划分

| 模块 | 职责 |
|------|------|
| **Content Script**（注入 YouTube） | 抓视频元信息（videoId/标题/频道）；上报播放进度（节流）；执行 seek；监听 SPA 导航（`yt-navigate-finish`）换视频自动刷新 |
| **Side Panel**（Preact） | 三 Tab + 设置页；虚拟滚动；选中交互 |
| **Background Service Worker** | 消息中枢；逐字稿获取服务（双通道）；翻译服务（双通道）；AI 服务（解释/摘要/润色）；存储读写 |
| **adapters/youtube.ts** | YouTube 字幕抓取隔离在独立适配器，改版只改一处；V3 新站点=新增适配器 |

### 4.2 逐字稿获取：双通道自动切换

| | 主通道：直抓字幕 | 兜底通道：Supadata API |
|---|---|---|
| 原理 | 从页面拿字幕轨道（`ytInitialPlayerResponse` → timedtext），或 innertube API | 第三方 REST API；无字幕视频由其 Whisper AI 生成逐字稿 |
| 成本 | 免费、无限 | 免费 100 次/月（个人够用），超出付费 |
| 触发 | 默认 | 视频无字幕 / 直抓失败时自动切换（需用户在设置里填 Supadata key） |
| 隐私 | 只连 YouTube | 视频 URL 经 Supadata 服务器（设置页注明） |

补充：字幕纠错。YouTube 自动字幕无标点、专有名词可能错 → 「LLM 纠错润色」开关：LLM 修正文本、保留时间戳。

### 4.3 翻译：双通道

- **免费通道（默认）**：Google 翻译免费端点，逐批并发；零配置开箱即用
- **LLM 通道（可选升级）**：OpenAI 兼容配置（base URL + key + model），每批约 40 句带上下文，术语一致；兼容 OpenAI/DeepSeek/智谱等
- 分批并发 + 进度指示；译文写回 `transcripts` 缓存，翻过不再翻

### 4.4 存储（IndexedDB + chrome.storage.local）

| 存储 | 内容 |
|------|------|
| `videos` | videoId、标题、频道、URL、字幕语言、抓取时间 |
| `transcripts` | videoId → `[{start, dur, en, zh}]`，含翻译状态 |
| `notes` | `{id, videoId, start, end, excerpt, annotation, type: value\|confusion, aiExplanation?, createdAt}` |
| `summaries` | `{videoId, content(结构化), model, generatedAt}` |
| chrome.storage.local | 设置：显示模式默认值、翻译通道、LLM 配置、Supadata key |

**密钥安全**：LLM key、Supadata key 仅存本机 `chrome.storage.local`（设置页粘贴注入），不硬编码、不打日志、不经过第三方（请求直达所配置的 API 地址）。

### 4.5 数据流示例（记一条笔记）

选中字幕 → Side Panel → 保存请求（消息）→ Background → IndexedDB `notes` → UI 刷新。

## 5. 错误处理

| 失败点 | 处理 |
|--------|------|
| 视频无字幕 | 自动切 Supadata（若已配置）；未配置则明确提示 + 引导配置 |
| 字幕接口请求失败 | 自动重试 1 次 → 仍失败切 Supadata → 都失败显示「重试」按钮 |
| 免费翻译限流 | 自动降速；显示进度与失败数；已完成译文不丢（缓存） |
| LLM key 无效/欠费 | 设置页明确报错；翻译可一键切回免费通道；AI 摘要/解释禁用并提示 |
| 超长视频摘要 | 分块处理，单块失败保留已完成块，可重试失败块 |
| YouTube 改版 | 抓取逻辑隔离在 `adapters/youtube.ts`，只改一处 |
| 数据安全 | 笔记实时落库；导出只读不删 |

## 6. 测试策略

1. **单元测试**（Vitest）：字幕解析（timedtext → 结构化）、翻译批量调度器、融合导出 Markdown 生成（时间戳排序、笔记嵌套规则——快照测试锁定格式）
2. **集成测试**：mock YouTube / Supadata / LLM 响应，测适配器与 AI 服务
3. **手动验收清单**：真实 YouTube 视频走完整流程（抓字幕 → 翻译 → 两种记笔记 → AI 解释 → 摘要 → 融合导出 → 历史库查看/跨视频跳转），每次发版前过一遍；插件自动化 E2E 成本高，V1 不做

## 7. 非目标（V1 明确不做）

- 飞书集成、跨视频分类、跨视频搜索（V2）
- 非 YouTube 站点（V3）
- 自建音频识别（已砍，Supadata 覆盖）
- 账号系统、云同步、多人协作
- 自动播放时自动生成摘要（token 花费必须用户手动触发）
